# STORYWEAVE 产品流程决策

> 文档状态：MVP 决策稿  
> 目标设备：手机优先，桌面端作为放大版  
> 本次实现：本地模板演示、浏览器本地书架持久化、本地分享预览

## 1. 一句话定义

织界是一款“由用户做少量关键选择、由系统持续长出章节”的互动小说阅读器。用户不需要写提示词，也不需要在开局把整本书写完；先搭好世界的约束和方向，阅读中只在真正影响命运的节点做决定。

产品的核心承诺是：**每一次决定都能改变下一页，但过去的书和其他世界线不会被悄悄改写。**

## 2. MVP 的范围与边界

### 2.1 本次必须完成

- 开局向导：选择分类、补充细节、可选的人生代入。
- 根据选择创建一份“世界线草稿”：世界规则、可修订的结局锚点、全书概要。
- 生成首章，并预取下一章；阅读第 N 章后按需生成第 N+1 章。
- 在决策点选择剧情；选择会使决策之后的未来正文失效，再从新的分支继续。
- 本地书架：保存连载本、完结本、合流本及阅读进度，刷新页面后仍能恢复。
- 两本本地书合流生成第三本独立的合流本，原书保持不变。
- 本地分享预览：为任意书生成只读快照，在“书城”中预览；不上传、不公开发布。

### 2.2 明确不在本次实现

- 真实 AI 调用、模型选择、流式输出、在线计费。
- 在线多人房间、好友系统、实时联机同步。
- 真实公开书城、评论、点赞、关注、搜索收录。
- 账号体系、云端同步、跨设备合并。
- 把整本书或所有可能分支一次性生成出来。

演示中用本地模板模拟“生成”和“合流”。模板接口要保留未来接入生成服务的边界，但当前不应为了模拟而引入网络请求或服务端依赖。

## 3. 体验原则：手机优先的 Apple 式简洁

### 3.1 页面只保留一条主路径

每个页面只回答一个问题，并只保留一个主操作：

| 页面 | 用户要回答的问题 | 主操作 |
| --- | --- | --- |
| 我的书架 | 我想继续哪一本？ | 继续阅读 |
| 开局向导 | 我想从哪里开始？ | 进入下一步 |
| 世界线确认 | 这条世界线是否符合我？ | 开始第一章 |
| 阅读页 | 我现在要怎么做？ | 做出选择 / 继续阅读 |
| 合流页 | 哪两本书要相遇？ | 创建合流本 |
| 书城预览 | 我愿意分享哪一个版本？ | 打开分享预览 |

高级设置、技术说明和诊断信息全部放到二级入口；不要把主流程拆成“模型、参数、Token、队列”等工程页面。

### 3.2 视觉与触控约束

- 手机单列布局优先，核心操作位于拇指可达区域；桌面端仅增加留白和辅助栏，不改变流程。
- 交互控件使用粗线条：手机端卡片、底部导航、主按钮以 2px 边框为基准，状态变化用颜色和位置表达，不依赖细小图标。
- 触控目标至少 44px；按下立即反馈，松开才提交，避免人为等待。
- 页面转场沿空间关系移动：向导前进向左、返回向右；阅读新章从当前章节自然接续；合流页从两本书向中间汇聚。
- 动画优先使用可中断的短弹簧或淡入；支持 `prefers-reduced-motion`，降级为淡入和颜色变化。
- 阅读页保持安静：正文、章节位置、决策卡是主层；半透明面板可承载辅助信息，但不遮挡正文。

## 4. 总体状态机

```text
书架
  ├─ 新建 → 开局向导（分类 → 细节 → 人生代入）
  │          ↓
  │       世界线草稿（规则 + 结局锚点 + 全书概要）
  │          ↓
  │       首章正文 + 下一章预取 → 阅读
  │                              ↓
  │                  阅读第 N 章 → 需要时生成第 N+1 章
  │                              ↓
  │                 决策 → 失效未来正文 → 新分支继续
  │
  ├─ 选择两本书 → 合流设置 → 创建第三本合流本（原书不变）
  │
  └─ 任意书 → 生成本地分享快照 → 书城预览
```

书的生命周期使用三个用户可理解的状态：

- **连载中**：世界线已建立，仍有可继续生成的章节。
- **已完结**：结局锚点已确认，最后一章已生成；可继续阅读和分享，但默认不再追加普通章节。
- **合流本**：由两本书派生的第三本独立作品；保留父书引用，可继续连载或完结。

“生成中、预取中、已失效、缓存命中”等是内部状态，不作为书的生命周期展示给用户。

## 5. 开局流程：先定方向，不写整本正文

### 5.1 第一步：选择分类

先选一个大分类，选项数量要少且有明显差异，例如奇幻、修仙、赛博、现实悬疑。分类只决定模板的语气、常见冲突和视觉封面，不锁死后续剧情。

交互规则：

- 单选；选中后立即显示一句解释和一个视觉预览。
- 不提供空白提示词框作为主路径；“自定义一句话”可以作为未来扩展。
- 用户可以返回改选，不产生新书，直到点击“开始织造”才创建草稿。

### 5.2 第二步：补充细节

将细节拆成有限的选择卡，而不是要求用户写设定文档：

- 世界气质：诗性冒险、悬疑推进、群像治愈等。
- 主角火种：能力、出身、性格或核心欲望。
- 关系偏好：独行、伙伴、宿敌、群像。
- 开局地点：从一个具体场景进入，而不是从百科介绍进入。

每张卡只表达一个变量，选项保持可替换。右侧或底部的“世界线预览”实时汇总选择，但不显示模型术语。

### 5.3 第三步：自愿的人生代入

人生代入完全自愿，默认关闭。开启后只收集用户主动填写的内容（例如称呼、一个愿望、一段想带入的关系），并在确认前明确说明用途：这些内容只影响主角的代入语气，不等于公开个人资料。

用户可以：

- 不代入，直接使用虚构主角。
- 只填写称呼，不提供现实经历。
- 随时关闭代入，之后章节使用虚构信息。

退出代入不删除已经生成的书；它只改变下一次生成所使用的主角资料。

### 5.4 建立世界线草稿

点击“开始织造”后，只建立三层结构，不写完整正文：

1. **世界规则**：世界能做什么、不能做什么，核心资源和冲突约束。
2. **结局锚点**：故事希望抵达的几个方向。锚点可在书中后续修订，不是不可逆的结局。
3. **全书概要**：章节节拍、主要角色弧线、伏笔和可能的结局方向；只存概要，不存所有章节正文。

完成后给用户一个“世界线确认”屏：可以修改设定、重新生成草稿或进入第一章。确认页展示的是可理解的摘要，不展示上下文拼接、模型调用或成本明细。

## 6. 阅读与生成：只向前生成一章

### 6.1 首次进入阅读

确认世界线后：

1. 生成第 1 章正文。
2. 同时预取第 2 章一份可替换的正文或草稿，供用户读完第 1 章后顺滑进入。
3. 只在本地保存当前章节和预取结果；不生成第 3 章，也不生成所有分支。

预取结果始终标记为“可被选择覆盖”。它不是向用户承诺的最终版本，决策发生后可以被丢弃并重写。

### 6.2 阅读第 N 章

阅读页只呈现以下内容：

- 章节标题、当前进度和正文。
- 角色或伏笔的少量上下文提示（可收起）。
- 决策点的 2–3 个选项；每个选项说明倾向或影响，不提前剧透完整结果。
- “继续阅读”或“做出选择”一个明确的主按钮。

当用户读完第 N 章：

- 若没有决策点，直接使用预取结果或生成第 N+1 章。
- 若有决策点，先保存选择，再使 N 章之后的未来正文失效，最后生成 N+1 章的新版本。
- 不回写已提交的第 N 章，不修改世界规则历史；只更新后续分支。

### 6.3 决策失效规则

每个章节正文带一个 `worldVersion` 和 `branchId`。选择发生时创建新的分支版本：

```text
选择前：chapter 1..N 已确认，chapter N+1 预取中
选择后：chapter 1..N 保留，chapter > N 的正文全部标记为 invalidated
继续生成：只生成新 branchId 下的 chapter N+1
```

失效不是删除用户的阅读痕迹：本地可以保留旧正文作为“旧时间线快照”，但主阅读路径只展示最新分支。MVP 可以只保留快照元数据和一键回到旧分支的入口，避免误以为系统偷偷改写了原故事。

### 6.4 生成状态的展示位置

主阅读页不显示以下技术状态：Token 数、模型名、请求队列、重试次数、缓存键、服务端延迟。它们会打断阅读，也不是用户完成选择所需的信息。

主阅读页只用用户语言表达可感知的状态：

- “下一页已准备好”
- “正在接住你的选择”
- “世界线需要一点时间长出下一页”
- “这条未来已被替换，旧版本仍在你的书架里”

如果调试或演示需要技术信息，放在设置中的“生成详情”抽屉或开发者面板，不进入阅读主路径。

## 7. 分层上下文与成本策略

生成上下文按稳定性分层，避免每一章重复携带整本书：

1. **稳定层**：世界规则、分类、不可违背的安全边界。
2. **可修订层**：结局锚点、主线方向、用户最新偏好。
3. **概要层**：全书概要、已确认章节的压缩摘要、角色弧线与伏笔清单。
4. **场景层**：当前章节、上一章必要片段、当前出场角色和地点卡。
5. **选择层**：本次选择及其影响；只带决策之后的必要状态。

章正文生成只取当前需要的层级。旧正文沉淀为摘要，重复生成时优先复用已确认章节和未失效的缓存；选择发生时只使未来正文失效，不连带重写稳定层和已确认章节。预取只做一个下一章，永远不做全树预生成。

这套策略的产品表述是“故事不会被提前写完”，不是向用户暴露具体成本数字。未来接入 AI 时，模板生成器应保持相同的输入输出边界，以便替换实现而不改变阅读流程。

## 8. 两书合流：生成第三本，原书只读

### 8.1 合流入口

用户从书架或“合流”页选择两本书。可选书必须有本地书架记录；不要求两本书来自同一分类。MVP 用本地模板模拟世界规则的冲突、共鸣和新入口。

合流页只让用户决定三件事：

- 哪两个主角在新世界相遇。
- 新世界优先保留哪一组规则。
- 第三本书从哪个场景开始。

### 8.2 产物与不可变性

点击“创建合流本”后生成一条全新的 `mergedBookId`：

- 新书拥有自己的世界规则、结局锚点、概要、章节和分支版本。
- 新书记录 `parentBookIds`，用于在详情页说明来源和回到原书。
- 原书的正文、进度、决策和分享快照全部保持不变。
- 合流失败或用户取消时，不产生半成品覆盖原书；可以丢弃未确认的合流草稿。

合流本的后续阅读与普通书一致：可以连载、做决策、完结和分享。合流是“派生一条新线”，不是把两本书拼接后回写。

## 9. 书架、分享与本地书城

### 9.1 书架展示

书架按用户最近阅读排序，并用清晰的状态标签区分：

- `连载中`：显示“继续阅读”和当前章节。
- `已完结`：显示“重读结局”和分享入口。
- `合流本`：显示来源两本书的缩略信息和继续阅读入口。

书架保存的是书的当前版本指针；失效分支和旧时间线放在书籍详情的“版本”抽屉中，不把用户推入复杂的分支管理页面。

### 9.2 发布快照（本地分享预览）

分享不是把实时书籍暴露出去，而是创建一个只读 `publishSnapshot`：

- 包含标题、封面、简介、书的生命周期状态、可读章节范围和生成时间。
- 固化当前 `branchId`、`worldVersion` 和章节内容，之后用户继续阅读不会改变这份预览。
- 默认移除人生代入中的私人字段；用户可在分享前逐项确认标题、简介和署名。
- 快照可撤销、可重新生成；撤销只影响本地预览，不删除原书。

本次的“书城”只是本地快照浏览器：可以在设备上查看、打开和取消分享，不上传服务器，不对其他真实用户公开。未来接入公开发布时，沿用快照作为审核和版本边界，不直接发布实时分支。

连载本、完结本和合流本都可以创建分享快照；状态显示在快照卡片上，避免用户误以为只有完结书才能分享。

## 10. 本地数据模型（供实现对齐）

字段是产品语义，不要求现在建立后端表：

```js
{
  id: 'book-local-id',
  kind: 'original' | 'merged',
  status: 'serializing' | 'completed' | 'merged',
  setup: {
    category: 'fantasy',
    details: {},
    immersive: false,
    persona: {}
  },
  world: {
    rules: [],
    endingAnchors: [],
    outline: {},
    version: 1
  },
  chapters: [
    {
      number: 1,
      status: 'confirmed' | 'prefetched' | 'invalidated',
      branchId: 'main',
      worldVersion: 1,
      body: '...'
    }
  ],
  decisions: [
    { chapter: 1, optionId: '...', branchId: 'branch-2' }
  ],
  parentBookIds: [],
  publishSnapshots: [],
  updatedAt: 0
}
```

本地持久化至少保证：书架列表、当前书籍、当前章节、最近选择、合流父书引用和分享快照在刷新后可恢复。实现可以先使用 `localStorage`；数据结构保持可迁移，未来接入云同步时不需要改变页面语义。

## 11. 隐私与信任

- 默认本地保存，未明确开启代入或分享前，不把用户输入发送到任何网络服务。
- 人生代入的开关、用途和清除入口要在同一页面说明；不要用默认勾选替代同意。
- 分享只基于用户确认过的快照；实时阅读状态、旧分支和私人代入字段不会自动附带。
- 删除书籍、撤销快照和清除代入资料都应有明确的结果反馈；删除前提供一次可理解的确认，避免误触。
- 若未来接入云端或 AI 服务，必须沿用“先确认、再发送；先快照、再发布”的顺序，并在设置中提供数据导出与删除入口。

## 12. 验收清单

以下条件全部满足，才算本 MVP 的流程闭环完成：

- 用户只用手机触控即可从书架进入向导，完成分类、细节和可选代入。
- 开局确认页能看到世界规则、结局锚点和全书概要，且没有整本正文。
- 进入阅读后有首章，并能看到下一章已准备或正在准备的用户级提示。
- 在第 N 章做选择后，主路径不会继续展示旧的未来正文；重新进入会得到新分支的第 N+1 章。
- 系统不会为了展示“可能性”而提前生成所有分支。
- 两本书合流后出现第三本书，两个原书的标题、章节、进度和快照均未改变。
- 连载本、完结本、合流本都能创建本地分享快照，并在书城预览中打开。
- 刷新页面后书架、阅读进度、分支和分享快照仍然存在。
- 阅读主页面没有 Token、模型、队列等后台技术状态；生成详情位于二级面板。
- 开启系统减少动态效果时，核心流程仍可完成，状态仍能被理解。

## 13. 后续接缝（本次不实现）

未来可在不改动上述页面逻辑的前提下替换三处实现：

1. 用真实生成服务替换本地模板生成器。
2. 用账号和云存储替换本地书架，并为合流增加在线邀请与权限。
3. 用服务端书城替换本地分享预览，继续以 `publishSnapshot` 作为公开发布的不可变版本。

这些能力都应接在现有状态边界之后，不能把模型控制台、多人房间或发布审核流程塞回主阅读页。
